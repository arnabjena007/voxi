Main Flow

1

User opens / or /?room=ABC123. Landing creates solo or multiplayer URL.

2

Room page mounts Three.js canvas, toolbar, player list, and room chat.

3

Multiplayer opens GET /ws/:code, sends binary Hello, receives Welcome snapshot.

4

Voxel edits, chat, presence, host change, and grid size move through the room actor and broadcast back.

5

Mic click fetches /voice/token, connects to LiveKit, then publishes/unmutes local audio.

Proto

Crate: voxi-proto

Shared Rust message contract, encoded with Postcard. The frontend mirrors this in TypeScript through frontend/src/proto.ts.

  • Hello: room, name, resume sequence, client token, avatar.
  • ClientMsg: Hello, Stroke, Chat, Guess, Game, Pong, React, Undo, Emote, Vote, Voxel, GridSize.
  • ServerMsg: Welcome, Resume, Stroke, Chat, Guess, Presence, Game, Ping, Bye, WordOptions, DrawerWord, JoinPending, DrawingFeedback, Emote, Voxel, GridSize.
  • RoomSnapshot: players, completed strokes, voxels, sequence, chat, game snapshot, grid size.

Room

Crate: voxi-room

Every room is one actor task. It owns the room state, accepts commands through an inbox, and fans out messages through broadcast/unicast channels.

  • RoomHandle.join: admits or gates a player, returns player id and receivers.
  • RoomHandle.send: forwards decoded client messages into room state.
  • RoomHandle.leave: removes player, broadcasts presence, transfers host.
  • Voxel path stores/replaces/removes blocks, validates grid limits, and broadcasts ServerMsg.Voxel.
  • Chat path stores ring history and broadcasts ServerMsg.Chat.

Server

Crate: voxi-server

Axum entrypoint. It validates room codes, upgrades WebSockets, records joins, serves metrics, mints LiveKit tokens, and serves the built frontend in production.

  • ws.rs: first-frame handshake, binary frame decode/encode, room relay loop.
  • rooms.rs: active room map and unique room-code creation.
  • voice.rs: LiveKit JWT minting.
  • tracker.rs: optional Turso-backed play stats.
  • bot.rs, matchmaker.rs, words.rs: backend drawing-game support still present.

Realtime Message Map

Browser Conn -> WebSocket /ws/:code -> decode_client_validated -> RoomHandle.send -> Room actor -> broadcast/unicast ServerMsg -> encode -> Browser handleMessage.

  • Voxel: client sends Voxel { x, y?, z, color, remove }; server broadcasts authoritative Voxel { seq, player, x, y, z, color, remove }.
  • Chat: client sends Chat { text }; server stores and broadcasts Chat { seq, player, text }.
  • Grid: host sends GridSize { size }; server broadcasts GridSize { size }.
  • Presence: join/leave broadcasts Presence { seq, joined, left }; host transfer currently arrives as Game.HostChanged.
  • Voice: browser does not send voice over the Voxi WebSocket; LiveKit carries audio after backend token minting.
